# Segmentation class fit for the intended vegetation

### Class policy must follow the target — 2026-09-05

**The terrain-only policy is wrong for the user's clumping-plant area of interest.** The user
identified the plant in Test_Grass2 as a required example, and made finding a class that fits the
intended region a prerequisite. This supersedes interpreting the earlier zero-overlap result as
a success for that target. It remains a description of the experimental lawn policy, not evidence
for selecting arbitrary vegetation.

The inspector now accepts diagnostic `--classes` overrides. On run
`20260814-174814-b245bc`, canonical source frame 80 (CLI index 79), the pinned Cityscapes B0 model
and a 0.5 winning-probability floor gave the following result against the exact recorded
`grass-exe1-wjhp:20260814-174814-b245bc#3` brush. Candidate masks were nearest-neighbour resampled
from 128x128 to the annotation's 576x1024 grid; its 20,892 painted pixels were not changed.

| Candidate policy | Annotated pixels recovered | Recall on the recorded brush |
|---|---:|---:|
| terrain | 0 | 0% |
| vegetation | 8,565 | 40.997% |
| terrain + vegetation | 8,565 | 40.997% |

`vegetation` is the semantically appropriate candidate for this vertically growing plant, but
the observed mask still misses most of the recorded height-bearing strip. The union adds lawn
without recovering any more of that strip. This brush is sparse object evidence, not a complete
annotation of all vegetation; outside-brush selections cannot be called false inclusions from
this reference alone. Whole-region precision and IoU remain unestablished. The earlier 41.6%
figure did not represent this exact probability-filtered, source-resolution comparison.
Removing the probability floor (`--classes vegetation --floor 0`, same frame and exact trial)
recovered 8,670 pixels, or 41.499%. Threshold relaxation therefore does not repair the missing
plant evidence; most of it is assigned to a different winning class.

Visual inspection of canonical frames 20, 40, 60, 80 and 90 found partial plant masks and missing
upper blades across views. Only frame 80 has the matching scored brush; the other four are visual
checks, not annotated recall trials. No candidate in this experiment establishes a satisfactory
automatic plant height. The production worker remains terrain-only and unvalidated; changing
the diagnostic does not change its masks or height definitions.

Cityscapes defines terrain to include horizontally spreading vegetation, soil and sand, while
vegetation includes vertically growing vegetation. Thus terrain is not a grass-only guarantee
even when the target is a lawn. Source: [Cityscapes class definitions, table 8](https://www.cityscapes-dataset.com/wordpress/wp-content/papercite-data/pdf/cordts2016cityscapes-supplemental.pdf).

**Evidence.** For each of `terrain`, `vegetation`, and `terrain,vegetation`, run
`node scripts/inspect.mjs segment 20260814-174814 --frame 79 --against
'grass-exe1-wjhp:20260814-174814-b245bc#3' --classes <policy> --json
--out .inspect/class-fit-review/<policy>.png`. The JSON's `selectedAgainst` scores the full
annotation grid; the existing per-class table scores the native logit grid. Visual contact sheet:
`node scripts/inspect.mjs segment 20260814-174814 --frames 19,39,59,79,89 --classes vegetation
--out .inspect/class-fit-review/vegetation-frames.png`. All ran locally on 2026-09-05 using cached
weights, with no cloud inference. Candidate labels are recorded in JSON and drawn on the image.

The verification harness passed all 681 tests in 50 files, fixture smoke, typecheck and Python
server contracts (`VERGE_PY=.venv/bin/python ./scripts/verify.sh`,
`.inspect/class-fit-review/verify.log`). The initial sandboxed attempt could not bind a loopback
test server; the successful run had loopback permission. All 26 frozen measurement trials also
replayed within 0.1 mm of their stored readings (`node scripts/collect-evidence.mjs`,
`.inspect/merge-review-regression.log`). These establish regression and reproducibility, not
vegetation-height accuracy. Invalid diagnostic class names were checked to fail explicitly.

## Earlier lawn-policy evidence, retained with its original scope

### Grass is segmented by class, and the class was chosen by measurement — 2026-09-04

`geometry/semantic-mask.ts` makes a grass mask from a model's logits using **one Cityscapes class,
`terrain` (id 9)**, dropping pixels under 0.5 probability rather than guessing. It stays pure.

**Why that class**, all on `20260814-174814-b245bc` frame 80 and reproducible with `node
scripts/inspect.mjs segment <run> --against <trial>`. Against the recorded Grass-Exe1 brush (20,892
px up one clump) `terrain` overlapped in **0 px**: the grass class does not swallow the bush, which
was the property in doubt. `vegetation` recovered 41.6% and `fence` the other 58.4%, thin blades
over a pale wall. `road` is unused — B2 called 9.74% of this frame `road` while looking at a wall,
B0 0.05%. ADE20k-B0, which has an explicit `grass` class, gave `water` 65.02% and `grass`
0.02% — the vehicle-mounted training domain does the work, not the label list. All else is
`excluded`, and `semantic-mask.test.ts` is where a promotion must be argued. The 0.5 floor comes from
38,898 `terrain` wins over 10 frames of this run and `20260814-164826-0e4e4c` (p5 0.509, p50 0.953):
bimodal, so it discards 4.24%, and a majority beats leading a 19-way split. The model is
`Xenova/segformer-b0-finetuned-cityscapes-1024-1024` @ `64e537ca2bf6bf2afc13727ee6bb61cfca9e1048` on
the `@huggingface/transformers@3.8.1` the app ships, 15.2 MB — less than its SlimSAM pair, fetched
once by the only file in `scripts/` that touches the network so the inspector still has none.

**Limits, seen not inferred.** Logits are 128x128 and deliberately not upsampled, since the grid
resamples onto the depth grid itself: a cell covers ~4.5x8 px of a 576x1024 frame. **Dry grass is
under-detected** — on `20260814-164826-0e4e4c` frame 21's green lawn gave 5,216 terrain px of 16,384
where 41 and 61, the same lawn brown, gave 225 and 540.
